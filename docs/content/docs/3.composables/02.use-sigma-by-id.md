## 用法

`useSigma()` 是 inject，只在子树内有效。工具栏、侧边面板、跨路由的代码拿不到上下文——给实例一个 `id`，就能在任何地方按 id 取：

:component-example{name="UseSigmaByIdExample"}

```vue
<script setup lang="ts">
const context = useSigmaById('main')

function zoomFromOutside() {
  context.value?.sigma.value?.getCamera().zoomIn({ duration: 300 })
}
</script>

<template>
  <button type="button" :disabled="!context" @click="zoomFromOutside">
    树外放大
  </button>

  <SigmaGraph id="main" :data="data" />
</template>
```

## 示例

### 返回的是计算属性

不是一次性查表。树外组件先于 `SigmaGraph` 渲染、跨路由预先持有引用都很常见，实例就绪后引用自动填上，卸载后变回 `undefined`。所以模板里的 `v-if="context"` 与 `:disabled="!context"` 是常规写法，不是防御性冗余。

### 多实例

一页里可以放任意多个实例，各自独立，给了 `id` 就登记进全局注册表：

:component-example{name="GraphMultiInstanceExample"}

::warning
每个 sigma 实例占 3 个 WebGL 上下文（`sigma-edges` / `sigma-nodes` / `sigma-hoverNodes` 三张画布），浏览器上限多为 16 个。超出后最早的上下文被强制丢弃、画布直接变空白，只在控制台留一行 `Too many active WebGL contexts`。列表页请做视口内懒挂载。
::

### id 冲突的告警会延后一拍

同 id 被两个实例占用时开发环境会告警，但判断推迟一个 `nextTick`：组件被替换时（HMR、路由切换、过渡动画）新实例在 setup 期就注册，旧实例要到 `onBeforeUnmount` 才注销，同步判断会把这种正常交接误报成冲突。真冲突时 `useSigmaById(id)` 取到的是**后挂载**的那个。

::note
注册表是模块级单例，写入受 `import.meta.client` 保护。服务端的 `sigma` 恒为 `null`，登记没有意义，这样也避免了跨请求残留。
::

## API

### useSigmaById()

`useSigmaById(id: MaybeRefOrGetter<string>): ComputedRef<SigmaContext | undefined>`{lang="ts-type"}

#### Parameters

::field-group
  :::field{name="id" type="MaybeRefOrGetter<string>" required}
  目标实例的 `id`，与 `SigmaGraph` 的 `id` prop 对应。接受 ref 或 getter，可动态切换目标。
  :::
::

#### Returns

计算属性，目标未挂载或已卸载时为 `undefined`。其值即 `useSigma()` 的返回结构，字段说明见 [`useSigma`](/docs/composables/use-sigma)。

### useSigmaIds()

`useSigmaIds(): ComputedRef<string[]>`{lang="ts-type"}

当前已挂载并登记了 `id` 的全部实例，随注册表增删自动更新。没给 `id` 的实例不会出现在这里。用于做实例切换器，或在开发期确认某个 id 是否真的登记上了。

```ts
import type { SigmaContext } from '@movk/sigma'
```
