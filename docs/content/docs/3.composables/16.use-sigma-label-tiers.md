## 用法

拉远之后节点变密，标签再全出就只剩噪声。档位先由 [`degreeToTier()`](/docs/utils/degree-to-tier) 写进属性，本 composable 只决定「当前该显示到哪一档」：

:component-example{name="UseSigmaLabelTiersExample" client-only="true" class="example-stage"}

```vue [UseSigmaLabelTiersPanel.vue]
<script setup lang="ts">
const { tier } = useSigmaLabelTiers({ breakpoints: [[2.6, 0], [1.3, 1]] })
</script>
```

`breakpoints` 按 `ratio` 降序，`ratio` 越大视野越广。上面这组读作：比例超过 2.6 只留 0 档，超过 1.3 留到 1 档，再近就不限制。自动 fit 之后比例通常落在 1 附近，默认值因此从 1.3 起跳。

### 为什么是置空 label 而不是隐藏

内部登记的归约把超档的节点 `label` 置为 `null`，节点本身照常渲染。这不是偷懒——sigma 的 `process()` 用**归约之后**的 `label` 喂标签网格，置空的节点会把同格的名额让给更重要的节点。改成 `hidden` 则连节点都没了，图的结构感随之丢失。

边标签跟着节点走：sigma 只在两端节点标签都显示时才画关系名，不需要额外处理。

### 为什么不用 labelRenderedSizeThreshold

sigma 自带的那个阈值比的是节点的**屏幕尺寸**。一旦设了 `zoomToSizeRatioFunction: () => 1`（节点在任何缩放下都一样大），屏幕尺寸与相机比例就脱钩了，阈值分不出级来。相机比例是唯一还在变的量。

### 刷新时机

相机每次移动都会触发回调，但只有档位**真正变化**时才写 ref、才重跑归约。逐帧刷新归约在几千个节点的图上是实打实的开销。

## API

### useSigmaLabelTiers()

`useSigmaLabelTiers(options?: UseSigmaLabelTiersOptions): UseSigmaLabelTiersReturn`{lang="ts-type"}

必须在 `SigmaGraph` 子树内调用。作用域销毁时自动解绑相机监听并注销归约。

#### Parameters

::field-group
  :::field{name="options" type="UseSigmaLabelTiersOptions"}

    ::::collapsible
      :::::field-group
        ::::::field{name="breakpoints" type="readonly SigmaLabelTierBreakpoint[]"}
        默认 `[[2.6, 0], [1.3, 1]]` —— 相机比例断点 `[ratio, tier]`，按 `ratio` 降序排列。比例大于 `ratio` 时只显示不高于 `tier` 的档位。
        ::::::

        ::::::field{name="attribute" type="string"}
        默认 `'labelTier'` —— 读取节点档位的属性名，需与 styles 里消费该档位的属性名一致。
        ::::::

        ::::::field{name="order" type="number"}
        默认 `100` —— reducer 链内次序，详见 [`useSigmaReducer()`](/docs/composables/use-sigma-reducer)。
        ::::::
      :::::
    ::::
  :::
::

#### Returns

::field-group
  :::field{name="tier" type="Readonly<Ref<number>>"}
  当前允许显示的最低档位。所有断点都未命中时为 `Infinity`，即不限制。
  :::
::

```ts
import type { SigmaLabelTierBreakpoint, UseSigmaLabelTiersOptions, UseSigmaLabelTiersReturn } from '@movk/sigma'
```
