## 用法

写一个谓词，返回 `true` 保留、`false` 隐藏：

:component-example{name="UseSigmaFilterExample"}

```vue [UseSigmaFilterPanel.vue]
<script setup lang="ts">
const { nodeFilter, only, reset, hiddenCount } = useSigmaFilter()

nodeFilter.value = (key, attributes) => attributes.category === 'Network Science'

only(neighborhood('n0')) // 或者直接给一批 key
</script>
```

### `hideDanglingEdges`

任一端点被隐藏时一并隐藏该边——否则会看到一堆连向空白处的断线。这条规则只在 `nodeFilter` 非空时生效，边的隐藏先看显式的 `edgeFilter`，再看它。

::component-example
---
name: UseSigmaFilterDanglingExample
options:
  - name: hideDanglingEdges
    label: hideDanglingEdges
    items: [true, false]
    default: true
---
::

## 示例

### 只动视图层

过滤落到 sigma 的 `isHidden` 状态上，**图数据一个字节都没动**：被隐藏的节点仍在 graphology 里，邻域计算与检索照常能看到它们；取消过滤是瞬时的；`graph.export()` 导出的仍是全量数据。需要真正删掉数据，那是 `graph.dropNode()` 的事。

选状态而不是「把颜色、透明度、图标逐个归零」是刻意的：`DEFAULT_STYLES` 把 `isHidden` 绑到 `visibility`，而 `visibility` 是独占语义字段，sigma 在顶点缓冲层面统一短路所有渲染层（标签、backdrop、标签背景、attachment 一起关掉）并让元素退出拾取缓冲。靠渲染字段表达隐藏则要求库知道你挂载了哪些层，永远做不完整。

::warning
这条绑定来自基础规则。把 `SigmaGraph` 的 `stylesBase` 设成 `'none'` 后 `isHidden` 不再产生任何视觉效果，得自己在 `styles` 里补一条 `visibility: { whenState: 'isHidden', then: 'hidden', else: 'visible' }`。详见 [`composeStyles`](/docs/utils/compose-styles)。
::

### sigma 至少要 4.0.0-beta.3

::warning
`4.0.0-beta.3` 之前的 sigma 对 `visibility: 'hidden'` 走的是 v3 遗留的「把整个顶点缓冲清零」分支，而 v4 的几何与颜色已经搬进纹理、缓冲里只剩纹理行号。清零后行号读回 `0`，而**索引 0 是一个真实存在的元素**——于是每个被隐藏的元素都会被画成 0 号元素的完整副本，`a_id = 0` 还会顶掉它的拾取 ID 让它点不中；边另有一处缺陷会让后续可见边的 dash/gap 错位。

症状是 payload 里第一个节点渲染异常且无法交互，实线关系被画成虚线、颜色错乱。上游在 `4.0.0-beta.3` 修掉了这两处，升上去即可，无需额外配置。
::

### 换谓词才触发重绘

库监听的是 `nodeFilter` / `edgeFilter` 两个 ref 的**赋值**，在既有闭包里改状态不会触发重绘：

```ts
// 错：谓词只赋值一次，之后改 keyword 不会重绘
nodeFilter.value = (_key, attrs) => String(attrs.label).includes(keyword.value)

// 对：每次都重新赋值
watch(keyword, (value) => {
  nodeFilter.value = (_key, attrs) => String(attrs.label).includes(value)
})
```

`only(null)` 只清 `nodeFilter`，`edgeFilter` 保持不变；`reset()` 才是两个都清。

### hiddenCount 是 O(n)

每次图变更或谓词更换都会全量遍历一遍节点，`nodeFilter` 为 `null` 时直接返回 `0`，不遍历。万级图上频繁触发要留意。

## API

### useSigmaFilter()

`useSigmaFilter(options?: UseSigmaFilterOptions): UseSigmaFilterReturn`{lang="ts-type"}

#### Options

::field-group
  :::field{name="hideDanglingEdges" type="boolean"}
  默认 `true` —— 任一端点被隐藏时一并隐藏该边。仅在 `nodeFilter` 非空时生效。
  :::
::

#### Returns

::field-group
  :::field{name="nodeFilter" type="Ref<SigmaNodePredicate | null>"}
  节点谓词，可写。为 `null` 表示不过滤。重新赋值才触发重绘。
  :::

  :::field{name="edgeFilter" type="Ref<SigmaEdgePredicate | null>"}
  边谓词，可写。为 `null` 表示不过滤。
  :::

  :::field{name="only()" type="(keys: Iterable<string> | null) => void"}
  只保留给定的节点。传 `null` 清空节点谓词，不影响边谓词。
  :::

  :::field{name="reset()" type="() => void"}
  清空所有过滤。
  :::

  :::field{name="hiddenCount" type="ComputedRef<number>"}
  当前被隐藏的节点数。无节点谓词时为 `0`。
  :::
::

`SigmaNodePredicate` 与 `SigmaEdgePredicate` 的形态都是 `(key: string, attributes: Attributes) => boolean`，返回 `true` 表示保留。类型从根出口取：

```ts
import type { SigmaEdgePredicate, SigmaNodePredicate, UseSigmaFilterOptions, UseSigmaFilterReturn } from '@movk/sigma'
```
