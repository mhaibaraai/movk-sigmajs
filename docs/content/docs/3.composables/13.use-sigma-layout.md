## 用法

一次性布局跑完就结束，调 `assign()`：

:component-example{name="UseSigmaLayoutExample" client-only="true" class="example-stage"}

```ts
const { assign } = useSigmaLayout('circular')
await assign()
```

迭代型布局要持续跑，调 `start()` / `stop()`：

:component-example{name="UseSigmaLayoutWorkerExample" client-only="true" class="example-stage"}

```ts
const { start, stop, isRunning } = useSigmaLayout('forceatlas2', {
  settings: { gravity: 1, scalingRatio: 10 }
})

await start()
setTimeout(stop, 3000)
```

::warning
布局会大幅改写坐标跨度：`circular` / `random` 默认只铺开 1~2 个单位，ForceAtlas2 会收敛到几十个单位。而 v4 的 `size` 是**图坐标单位**，跨度一缩节点就成倍胀大，画面直接糊掉。

上面两个示例都传了 `itemSizesReference: 'screen'` 让 `size` 退回像素语义。取舍与其他解法见[节点尺寸与坐标量级](/docs/guides/node-size)。
::

### 两类布局

::field-group
  :::field{name="迭代型（forceatlas2、noverlap）"}
  `isSupervised` 为 `true`。支持后台持续迭代，可以放进 worker 不阻塞主线程。
  :::

  :::field{name="一次性（circular、circlepack、random）"}
  `isSupervised` 为 `false`。算一遍写回坐标就结束，`start()` 在这类布局上等价于 `assign()`。
  :::
::

`isSupervised` 是**普通布尔值，不是 ref**——布局名在调用时就定了，不会变。

### assign 与 start 的区别

`assign()` 永远是一次性的，**忽略 `worker` 选项**。它适合「摆一次位就不动了」的场景，比如加载完数据先跑一遍 ForceAtlas2 定型。

`start()` 只在「迭代型布局 + `worker: true`」时才真的开 worker。否则退化成一次性计算，而且**不会**把 `isRunning` 置为 `true`：

```ts
const { start, isRunning } = useSigmaLayout('circular')
await start() // 跑了一遍就结束，isRunning 始终是 false
```

### worker 的生命周期

worker 会持续占用线程，组件卸载或 HMR 时不释放就泄漏。库在作用域销毁时自动 `kill()`，不必自己接 `onUnmounted`。

`stop()` 只暂停迭代，worker 还在，`start()` 可以再启动。`kill()` 才是真的销毁。

::warning
supervisor 绑定的是**首次调用 `start()` 时**的图实例。图实例被整个替换后（不是内容变化，是换了个 `Graph` 对象），必须先 `kill()` 再重新 `start()`，否则布局还在给旧图算坐标。
::

### 与拖拽互斥

::warning
迭代型布局在跑时会持续回写坐标，[`useSigmaDrag()`](/docs/composables/use-sigma-drag) 的拖拽结果会被立刻覆盖。需要手动摆位时先 `stop()`。
::

### settings 整体透传

`settings` 直接交给底层算法，不做键过滤。ForceAtlas2 两条路径都以 `inferSettings()` 的推断结果为基座，你传的键覆盖在上面：

```ts
useSigmaLayout('forceatlas2', {
  settings: { gravity: 1 } // 其余仍用 inferSettings 推断出的值
})
```

::note
全部布局包都是**可选 peer**，用到时才动态导入，未安装时抛出的错误里带有安装命令：

- `forceatlas2` → `graphology-layout-forceatlas2`
- `noverlap` → `graphology-layout-noverlap`
- `circular` / `circlepack` / `random` → `graphology-layout`
::

## API

### useSigmaLayout()

`useSigmaLayout(name: SigmaLayoutName, options?: UseSigmaLayoutOptions): UseSigmaLayoutReturn`{lang="ts-type"}

#### Parameters

::field-group
  :::field{name="name" type="SigmaLayoutName" required}
  布局算法名，取值为 `'forceatlas2'`、`'noverlap'`、`'circular'`、`'circlepack'`、`'random'`。
  :::

  :::field{name="options" type="UseSigmaLayoutOptions"}
  布局选项。

    ::::collapsible
      :::::field-group
        ::::::field{name="worker" type="boolean"}
        默认 `true` —— 迭代型布局是否放到 worker 里跑，避免阻塞主线程。`assign()` 不受此项影响。
        ::::::

        ::::::field{name="settings" type="Record<string, unknown>"}
        透传给底层算法的设置，不做键过滤。ForceAtlas2 下覆盖在 `inferSettings()` 的推断值之上。
        ::::::

        ::::::field{name="iterations" type="number"}
        默认 `100` —— 非 worker 模式下 forceatlas2 的迭代次数。
        ::::::
      :::::
    ::::
  :::
::

#### Returns

::field-group
  :::field{name="isSupervised" type="boolean"}
  该布局是否支持后台持续迭代。普通布尔值，不是 ref。
  :::

  :::field{name="isRunning" type="Readonly<Ref<boolean>>"}
  worker 是否正在运行。一次性布局上恒为 `false`。
  :::

  :::field{name="assign()" type="() => Promise<void>"}
  计算一次并写回节点坐标，然后触发重绘。始终是一次性的，忽略 `worker`。
  :::

  :::field{name="start()" type="() => Promise<void>"}
  启动持续迭代。非迭代型布局或 `worker: false` 时退化为 `assign()` 的行为。
  :::

  :::field{name="stop()" type="() => void"}
  停止迭代。worker 仍存活，可再次 `start()`。
  :::

  :::field{name="kill()" type="() => void"}
  终止并释放 worker。作用域销毁时自动调用。
  :::
::

`settings` 的具体键见 [graphology 布局文档](https://graphology.github.io/standard-library/layout-forceatlas2.html)。本库自己的类型从根出口取：

```ts
import type { SigmaLayoutName, UseSigmaLayoutOptions, UseSigmaLayoutReturn } from '@movk/sigma'
```
