## 用法

`SigmaGraph` 内部用它把基础规则、用户的 `styles` 与库内规则拼成一份声明，通常不必直接调用。

`composeStyles(...sources: SigmaStyles[]): SigmaStyles`{lang="ts-type"}

:component-example{name="ComposeStylesExample"}

## sigma 是整体替换，不是合并

传给 sigma 的 `styles.nodes` 会**顶掉整个** `DEFAULT_STYLES.nodes`：

```js
// sigma 源码
nodes: styles.nodes ?? DEFAULT_STYLES.nodes,
edges: styles.edges ?? DEFAULT_STYLES.edges,
```

只声明一条 `color` 规则，丢掉的却是一整套：

::field-group
  :::field{name="visibility"}
  最要命的一条。`whenState: 'isHidden'` 的绑定丢了之后，[`useSigmaFilter()`](/docs/composables/use-sigma-filter)、`SigmaLegend` 与 [`useSigmaState()`](/docs/composables/use-sigma-state) 的隐藏路径全部**静默失效**——过滤照常算出该藏谁、状态照常写进实例，画面上却什么都没变。
  :::

  :::field{name="label 的属性绑定"}
  节点标签直接消失，上面示例切到 `none` 就能看到。
  :::

  :::field{name="悬浮反馈"}
  `size` 的悬浮放大、`labelVisibility` 的悬浮强显，以及六项 `backdrop*` 标签背板。
  :::

  :::field{name="size / color 的属性绑定与兜底值"}
  自己的规则没覆盖到的那部分节点会掉回 sigma 的硬编码默认值。
  :::
::

::note
`x` / `y` 是唯一的例外：`postEvaluateNode()` 在规则求值之后有一段兜底，样式没给就直接读节点属性，所以坐标不会因此丢失。别的字段都没有这层保险。
::

`SigmaGraph` 因此默认把用户规则合成在基础规则之后，`stylesBase` 控制用哪一套：

::field-group
  :::field{name="'default'"}
  默认值 —— 与 `DEFAULT_STYLES` 合成，含深度层。
  :::

  :::field{name="'depthless'"}
  与 `DEPTHLESS_STYLES` 合成，不声明深度层，自定义 `primitives.depthLayers` 时用。
  :::

  :::field{name="'none'"}
  不带任何基础规则，全部交给用户。上面示例切到这一档就能看到坍塌。
  :::
::

## 拼接顺序即覆盖顺序

sigma 的规则数组按序求值，后者覆盖前者。最终交给构造函数的次序固定为：

```text
基础规则 → 用户的 styles → 库内规则
```

库内规则排在最后，[`useSigmaSelection()`](/docs/composables/use-sigma-selection) 的淡出与 [`useSigmaLabelTiers()`](/docs/composables/use-sigma-label-tiers) 的标签分级才盖得住用户自定义的配色。想完全自己控制这两处外观，把 `dim` 关掉、不使用分级即可。

单条规则与规则数组一视同仁地摊平，`undefined` 的来源直接跳过；某一侧全空时不产出该键，交回 sigma 自己的默认值。
