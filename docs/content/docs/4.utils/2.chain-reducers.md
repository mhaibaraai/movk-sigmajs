## 用法

sigma 的 `nodeReducer` 与 `edgeReducer` 各只接受一个函数，后设置的会覆盖先设置的。而选中高亮、过滤、图例显隐都要往显示数据上叠一层，`chainReducers` 就是把它们合成一条链的地方。

日常不必直接调用——[`useSigmaReducer()`](/docs/composables/use-sigma-reducer) 登记的条目由 `SigmaGraph` 自动合成。下面的示例经 `nodeReducer` prop 传了一条「统一放大」的基座归约，子组件再登记一条「按分类着色」，两条都生效：

### 用户自带的归约位于链首

`nodeReducer` / `edgeReducer`（`SigmaGraph` 的独立 props）永远是链的基座，库注册的条目按 `order` 升序叠在其后。内置条目的次序是过滤 `50`、选中高亮 `100`、图例 `200`。

::warning
`nodeReducer` 在 v4 已不是 `Settings` 的键，`sigma.setSetting('nodeReducer', fn)` 既不生效也过不了类型检查。要往链上加归约请用 `useSigmaReducer()`；链首基座走 `SigmaGraph` 的 `nodeReducer` / `edgeReducer` prop。
::

### 累积对象只在本次调用内有效

链在入口处复制一份入参，之后所有环在这个副本上原地累积。调用方传入的原始对象不受影响，但每个归约函数收到的 `data` 是链内复用的累积对象：

```ts
useSigmaReducer({
  node: (key, data) => {
    cache.set(key, data) // 错误：持有的是共享累积对象，后续环写入的值会串进来
    cache.set(key, { ...data }) // 正确：要跨调用留存必须复制
    return {}
  }
})
```

合成后的函数每帧对每个节点与每条边各跑一次，是热路径。先复制再原地累积，对象分配从「每条归约一个」降到「每次调用一个」。

### 单条也要包一层

只有一个归约函数时链依然会包装它，而不是直接交给 sigma。因为 sigma 把归约的返回值当作**完整**的显示数据用，缺 `x` / `y` 会直接抛错。链的契约是「返回补丁」，单条与多条必须一致——否则同一个归约函数在链上多一个同伴就换一种语义。

全部为空位（`null` / `undefined`）时返回 `null`，正好是 sigma 对「无归约」的表示。

## API

### chainReducers()

`chainReducers<D>(reducers: Array<SigmaReducer<D> | null | undefined>): SigmaReducer<D> | null`{lang="ts-type"}

#### Parameters

::field-group
  :::field{name="reducers" type="Array<SigmaReducer<D> | null | undefined>" required}
  待合成的归约函数，按数组顺序执行。空位会被跳过。
  :::
::

#### Returns

合成后的单个归约函数，签名与入参一致；全部为空位时返回 `null`。

`SigmaReducer<D>` 的形态是 `(key: string, data: Attributes) => Partial<D>`，`D` 取 `NodeDisplayData` 或 `EdgeDisplayData`，两者都来自 `sigma/types`。本库自己的类型从根出口取：

```ts
import type { SigmaReducer } from '@movk/sigma'
```
