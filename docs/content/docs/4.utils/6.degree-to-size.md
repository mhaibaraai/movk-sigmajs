## 用法

度数是最直接的重要性信号，把它映射到节点尺寸，枢纽就会自然浮出来：

:component-example{name="DegreeToSizeExample" client-only="true" class="example-stage"}

度数先按全图的最小、最大值归一到 `0..1`，取 `sqrt` 后再经 `@movk/core` 的 `mapRange(..., { clamp: true })` 落到目标区间。

### 为什么不是线性

度数分布普遍偏斜——大量叶子节点配少数枢纽。线性映射下，度数 1 与 2 的差距被压成区间里极小的一段，绝大多数节点挤在下界，只有枢纽独占上界，观感就是「一堆小点加几个大球」。而节点尺寸是按**面积**被感知的，半径 ∝ sqrt(度数) 才让面积正比于度数。sqrt 曲线不改变端点取值，只把中间段整体抬高：度数 1..3 映射到 `[4, 20]` 时，度 2 从线性的 12 抬到约 15.3。

### 只返回映射，不写图

函数不碰图数据。是把结果落到 `size` 属性、还是交给 reducer 只影响显示，由调用方决定——两种做法的区别很实在：

```ts
// 写进属性：持久化，会被 graph.export() 带走，也参与后续的 applyGraphDiff 比对
const sizes = degreeToSize(graph)
for (const [node, size] of Object.entries(sizes)) {
  graph.setNodeAttribute(node, 'size', size)
}

// 只走 reducer：纯显示层，数据保持干净，换算规则随时可撤
const sizes = computed(() => degreeToSize(toRaw(graph.value)))
useSigmaReducer({
  node: key => ({ size: sizes.value[key] })
})
```

服务端下发的数据里若已有业务含义的 `size`，走 reducer 那条更稳妥——不会把原值覆盖掉。

::note
全图度数相同时输入区间退化，所有节点取目标区间的**下界**。空图返回 `{}`。
::

## API

### degreeToSize()

`degreeToSize(graph: Graph, range?: [number, number]): Record<string, number>`{lang="ts-type"}

#### Parameters

::field-group
  :::field{name="graph" type="Graph" required}
  源 graphology 实例，只读不改。
  :::

  :::field{name="range" type="[number, number]"}
  默认 `[4, 20]` —— 目标尺寸区间 `[min, max]`，度数最低的节点取 `min`，最高的取 `max`，中间按 sqrt 曲线插值。
  :::
::

#### Returns

`Record<string, number>`，节点 key 到 size 的映射表。
