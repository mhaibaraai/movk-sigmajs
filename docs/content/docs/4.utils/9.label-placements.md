## 用法

标签放在哪一侧不该是固定的：节点连线最密的方向也是最容易压到边和邻居标签的方向。把邻居的单位向量加起来，取反就是最空的一侧：

:component-example{name="LabelPlacementsExample"}

```ts
const placements = labelPlacements(graph)
for (const [node, placement] of Object.entries(placements)) {
  graph.setNodeAttribute(node, 'labelPlacement', placement)
}
```

写进属性后由 styles 的 `labelPosition` 读取。返回值是 sigma 的 `LabelPosition`，取 `'above'` / `'below'` / `'left'` / `'right'` 四个方位之一。

### 必须在布局之后调用

方位完全由邻居的相对位置决定，坐标一变结论就作废：

```ts
forceAtlas2.assign(graph, { iterations: 200 })
labelPlacements(graph) // 顺序反过来算出来的是初始坐标下的方位
```

### 横向偏置

标签是一条横向的矩形，占的宽度远大于高度。同样是斜角方向，放到左右两侧比放到上下更容易撞上别的东西。因此只有横向分量明显压过纵向时才甩到左右，默认阈值是 1.6 倍：

```ts
labelPlacements(graph, { horizontalBias: 1 }) // 退化成按象限均分
```

### 坐标系

图坐标 y 轴向上，屏幕 y 轴向下，函数内部已经翻转过：邻居在图坐标里的**上方**，标签返回的是 `'bottom'`。孤立节点没有邻居可参考，一律取 `'bottom'`。

## API

### labelPlacements()

`labelPlacements(graph: Graph, options?: LabelPlacementsOptions): Record<string, SigmaLabelPlacement>`{lang="ts-type"}

#### Parameters

::field-group
  :::field{name="graph" type="Graph" required}
  源 graphology 实例，只读不改。节点须已有 `x` / `y`。
  :::

  :::field{name="options" type="LabelPlacementsOptions"}

    ::::collapsible
      :::::field-group
        ::::::field{name="horizontalBias" type="number"}
        默认 `1.6` —— 横向偏置。横向分量超过纵向分量这么多倍时，标签才甩到左右两侧。
        ::::::
      :::::
    ::::
  :::
::

#### Returns

`Record<string, SigmaLabelPlacement>`，节点 key 到 `'top' | 'bottom' | 'left' | 'right'` 的映射表。

```ts
import type { LabelPlacementsOptions, SigmaLabelPlacement } from '@movk/sigma'
```
