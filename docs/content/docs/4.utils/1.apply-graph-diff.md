## 用法

`SigmaGraph` 的 `data` 通道内部就走这个函数。换掉整个 `data` 只会重建差异部分——其余节点不重建、布局不丢、相机不跳：

:component-example{name="ApplyGraphDiffExample" client-only="true" class="example-stage"}

直接调用的场景是自己持有 graphology 实例（`graph` 通道）时：

```ts
const graph = shallowRef(new Graph())

watch(data, (next) => {
  applyGraphDiff(graph.value, next, { preservePositions: true })
})
```

::note
graphology 实例本身就是可变数据结构，这里直接 mutation 是有意为之，也是本库不可变原则的唯一例外。
::

### 保留坐标

节点属性按新数据整体替换，唯一例外是 `preservePositions` 下的 `x` / `y`：新数据显式给出时以新值为准，未给出则沿用图上现有坐标。

力导向布局跑完后坐标只存在于图上、不在服务端返回的数据里。关掉这个开关，每次数据刷新整张图都会跳回初始坐标。

### 增量合入

`prune` 默认会移除新数据中不存在的节点与边。做「概览 + 邻域按需展开」时必须关掉，否则每展开一个节点就会把其余部分清空：

```ts
const neighbors = await $fetch(`/api/graph/nodes/${id}/neighbors`)
applyGraphDiff(graph, neighbors, { prune: false })
```

增量合入时边可能指向尚未加载的节点，这属于正常情况——函数会跳过并在开发环境给出警告，而不是抛出难以定位的 `NotFoundGraphError`。

### 多重图的边身份

多重图上无 `key` 的边一律新增：按端点匹配会把三条 `a → b` 压成一条。代价是每次全量同步边 key 会重新生成。需要稳定边身份，或用 `prune: false` 增量合入时，请在数据里显式给出 `key`。

## API

```ts
function applyGraphDiff(
  graph: Graph,
  next: SerializedGraph,
  options?: ApplyGraphDiffOptions
): void
```

### 参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `graph` | `Graph` | 目标 graphology 实例，就地修改 |
| `next` | `SerializedGraph` | 新数据，类型来自 `graphology-types` |
| `options` | `ApplyGraphDiffOptions` | 行为选项 |

### ApplyGraphDiffOptions

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `preservePositions` | `boolean` | `true` | 已存在节点若在新数据中未显式给出 `x` / `y`，保留图上现有坐标 |
| `prune` | `boolean` | `true` | 移除新数据中不存在的节点与边。增量合入局部数据时应关闭 |

### 类型

```ts
import type { ApplyGraphDiffOptions } from '@movk/sigma'
```
