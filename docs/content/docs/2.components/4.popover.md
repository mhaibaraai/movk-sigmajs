## 用法

与 `SigmaTooltip` 的区别在于「常驻」与「可交互」：提示层跟着指针走、鼠标穿透，浮层则停在那里，里面的按钮和链接都能点。

典型用法是配合 `useSigmaSelection()`，点节点开详情：

:component-example{name="PopoverExample"}

```vue [PopoverPanel.vue]
<script setup lang="ts">
const { selected } = useSigmaSelection()
const open = ref(true)
</script>

<template>
  <SigmaPopover v-model:open="open" :node="selected">
    <template #default="{ node, attributes, close }">
      <strong>{{ attributes.label ?? node }}</strong>
      <button type="button" @click="close">
        ×
      </button>
    </template>
  </SigmaPopover>
</template>
```

::note
`useSigmaSelection()` 与 `SigmaPopover` 都要在 `SigmaGraph` 子树内，所以消费上下文的这一层总是独立组件，而不是写在页面外壳里。
::

### 两个开关是与的关系

显示需要 `open` 为真**且** `node` 非空。`node` 为 `null` 时浮层不显示，`open` 的值保持不变——把 `node` 绑到选中项、`open` 绑到用户的关闭动作，两者互不干扰：

```ts
watch(selected, (key) => {
  if (key) {
    open.value = true // 换节点时重新打开，因为上一次可能被用户关掉了
  }
})
```

`open` 默认为 `true`。不写 `v-model:open` 时浮层的显隐完全跟随 `node`。

### 内部可交互

`.sigma-popover` 把 `pointer-events` 恢复成了 `auto`（`.sigma-overlay` 基类是 `none`），所以插槽里的按钮、输入框、滚动区域都正常工作。

作用域里的 `close()` 就是把 `open` 置为 `false`，供插槽内的关闭按钮直接调用——接管外观时不必自己往上传状态。

浮层默认水平居中、底边贴在节点上方，靠 CSS 的 `translate: -50% -100%` 实现；`offset` 默认 `[0, -16]` 再往上推一段，留出节点半径的空间。

## API

### Props

:component-props{slug="SigmaPopover"}

### Emits

:component-emits{slug="SigmaPopover"}

`update:open` 由 `v-model:open` 使用，也可单独监听。

### Slots

:component-slots{slug="SigmaPopover"}

默认插槽作用域：

::field-group
  :::field{name="node" type="string"}
  当前锚定的节点 key。插槽仅在浮层可见时渲染，因此这里不会是 `null`。
  :::

  :::field{name="attributes" type="Attributes"}
  该节点的完整属性对象，类型来自 `graphology-types`。节点已被移除时为 `{}`。
  :::

  :::field{name="close()" type="() => void"}
  关闭浮层，等价于把 `open` 置为 `false`。
  :::
::
