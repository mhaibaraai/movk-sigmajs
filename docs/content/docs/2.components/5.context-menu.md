## 用法

`target` 决定右键哪里会弹菜单，默认只接管节点：

:component-example{name="ContextMenuExample" client-only="true" class="example-stage"}

点击节点或画布空白处会关闭菜单，插槽作用域里也带了 `close`，供菜单项执行完自行收起。

### 压掉原生菜单需要两步

`event.preventSigmaDefault()` 只拦 sigma 自己的默认行为，浏览器菜单照样弹出。所幸 sigma 的鼠标捕获器直接监听 DOM 的 `contextmenu` 且没有调用 `preventDefault()`，而事件处理函数是在那个监听器里同步执行的——于是组件在此把原生事件一并拦下。

这件事只在**确实接管的目标**上做。`target` 里没写 `'stage'` 时，在空白处右键仍然弹浏览器自己的菜单，不影响「在图上右键另存为图片」这类原生能力。

### stage 命中走另一套坐标

节点与边的命中锚定到节点（边取 `graph.source(edge)`），走 framed 坐标换算；空白处命中没有节点可锚，组件把视口坐标转成图坐标后交给 `SigmaOverlay` 的 `position` 通道，走原始图坐标换算。两条路径的结果一致，但作用域里的字段会有区别：

::field-group
  :::field{name="type === 'stage'"}
  `id` 为 `null`，`attributes` 为 `{}`。菜单项通常是「在此处新建节点」这类与具体图元无关的操作。
  :::
::

菜单没有 `translate` 偏移，从光标右下方展开，`offset` 默认 `[4, 4]` 留出一点间隙。

::warning
`target` 含 `'edge'` 时，必须先在 `settings` 里开 `enableEdgeEvents: true`，否则边上的右键事件根本不会触发。
::

## API

### Props

:component-props{slug="SigmaContextMenu"}

### Slots

:component-slots{slug="SigmaContextMenu"}

默认插槽作用域：

::field-group
  :::field{name="id" type="string | null"}
  命中的节点或边的 key；`type` 为 `'stage'` 时为 `null`。用 `id` 而非 `key`，后者是 Vue 的保留属性。
  :::

  :::field{name="type" type="'node' | 'edge' | 'stage'"}
  命中的图元类型。
  :::

  :::field{name="attributes" type="Attributes"}
  该图元的完整属性对象，类型来自 `graphology-types`。`stage` 命中或图元已被移除时为 `{}`。
  :::

  :::field{name="close()" type="() => void"}
  关闭菜单。
  :::
::

### Expose

经 [`useTemplateRef`](https://vuejs.org/api/composition-api-helpers.html#usetemplateref) 访问该组件实例。

::field-group
  :::field{name="close()" type="() => void"}
  关闭菜单，与插槽作用域里的同名方法一致。
  :::
::
