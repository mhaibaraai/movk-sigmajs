## 用法

放进 `SigmaGraph` 即可工作，无需接线。不给插槽时展示节点或边的 `label`，缺失则退回图元的 key。

与 `SigmaPopover` 的分界在于「跟指针走」和「鼠标穿透」：提示层由命中事件驱动，鼠标事件穿透到画布上，里面放不了可点的东西。

### `trigger`

`hover` 跟着指针进出，`click` 点中才打开。两种触发下点击画布空白处都会关闭：

::component-example
---
name: TooltipTriggerExample
options:
  - name: trigger
    label: trigger
    items: [hover, click]
    default: hover
---
::

### `target`

决定响应哪类图元。边没有单一锚点，组件退化到 `graph.source(edge)` 定位——提示层贴在边的**源节点**上，而不是鼠标位置或边的中点：

::component-example
---
name: TooltipTargetExample
options:
  - name: target
    label: target
    items: [node, edge, both]
    default: node
---
::

::warning
`target` 含 `'edge'` 或 `'both'` 时，必须先在 `settings` 里开 `enableEdgeEvents: true`。这是 sigma 的默认行为——边的命中检测有额外开销，默认关闭——不是本库的限制。
::

### `offset`

相对锚点的像素偏移，默认 `[0, -12]`。`.sigma-tooltip` 已经用 CSS `translate: -50% -100%` 做好了水平居中与底边贴合，`offset` 在这之上再推像素，用途是让开节点半径：

::component-example
---
name: TooltipOffsetExample
options:
  - name: offsetY
    label: offset y
    type: number
    default: -12
---
::

## 示例

### 默认插槽

插槽以 `{ id, type, attributes }` 暴露命中项，`attributes` 是该节点或边的完整属性对象，图元已从图上移除时为 `{}`：

:component-example{name="TooltipSlotExample"}

::note
键名是 `id` 而不是 `key`——`key` 是 Vue 的保留属性，作用域里放不进去。`SigmaContextMenu` 同理。
::

### `hide()`

与 `SigmaPopover` / `SigmaContextMenu` 不同，本组件的插槽作用域里**没有** `close`：提示层跟着指针走，没有「用户主动关掉」这回事。确实需要程序化关闭时经模板 ref：
