## 用法

`SigmaGraph` 在客户端创建 Sigma 实例与 graphology 图，把上下文下发给子树。所有 composable 都要在它的默认插槽内调用。

### `data`

数据有两条互斥通道：传 `data` 由库经 [`applyGraphDiff`](/docs/utils/apply-graph-diff) 增量同步，传 `graph` 则库完全不碰数据，只负责渲染与生命周期。

:component-example{name="GraphBasicExample" :collapse="true"}

::note
组件本身不带高度。画布用 `height: 100%` 占满容器，所以外层必须给出确定的高度，否则整张图不可见。
::

### `graph`

传 `graph` 时库完全不碰数据，只负责渲染与生命周期。图可以用 graphology 生态的任何方式操作，sigma 靠图事件自动重绘：

:component-example{name="GraphExternalExample"}

::warning
这条通道下 `data` 与 `diffOptions` 都不生效。适合数据本来就由别处（Pinia、自己的 diff 逻辑、上游算法库）掌控的场景。
::

### `settings`

`settings` 整体交给 sigma，不逐字段枚举也不过滤未知键。v4 的 `Settings` 只管行为与性能，视觉规则在 `styles` 里。下面这个示例传入一个库不认识的配置键，再从 `sigma.getSettings()` 原样读回：

:component-example{name="GraphSettingsExample"}

::note
模块选项里的全局 `settings` 与组件级 `settings` 深度合并后一起透传，组件级优先。
::

### `events`

`emits` 覆盖 sigma 事件全集，node / edge / stage 三组直接可监听，payload 类型与上游一致：

:component-example{name="GraphEventsExample"}

::warning
边事件需要先在 `settings` 里开 `enableEdgeEvents: true`，这是 sigma 的默认行为，不是本库的限制。
::

### `styles`

`styles` 是 v4 的声明式视觉层，与 `settings` 分工明确：`settings` 只管行为与性能，视觉规则一律写在 `styles` 里。每条规则有三种取值形式——常量、`{ attribute, dict, defaultValue }` 分类映射、`{ attribute, min, max, minValue, maxValue }` 数值映射。

:component-example{name="GraphStylesExample"}

::note
`styles` 在构造 sigma 实例时读取，引用变了会重建实例并打一行警告。要么把它提到 setup 顶层保持引用稳定，要么像上面这样等数据就绪后再挂载组件。
::

### 节点标签的字形图集

节点标签走 SDF 渲染：字形先按某个**源字号**烘进一张 2048×2048 的图集纹理，再按 `styles` 里的 `labelSize` 缩放绘制。源字号由 `labelAtlasFontSize` 决定，默认 `64`，与边标签的图集一致。

sigma 上游给节点标签用的是 `64 × devicePixelRatio`。2 倍屏上单个字形连同 buffer 占约 144px，一页只装得下约 190 个，中文字形集轻易超过——溢出后游标翻到第二页，而上游只上传第一页，翻页那一步还会把第一页截成 1px 宽。症状是**节点标签整体消失**：边标签因字形少仍正常，1 倍屏也正常，控制台没有任何报错。本库因此把默认值压回 64，一页可容约 600 个字形。

::note
SDF 是矢量距离场，源字号减半对 12~24px 的显示字号没有可见影响。Latin 字形集本来就不会溢出，想在很大的 `labelSize` 下更锐利，把 `labelAtlasFontSize` 调回 `128` 即可。
::

### 自定义状态标志位

`customNodeState` / `customEdgeState` / `customGraphState` 声明自定义状态的默认值，键名不能与 `BaseNodeState` 等内置状态冲突。声明之后 [`useSigmaState()`](/docs/composables/use-sigma-state) 就能读写它们，`styles` 里用 `matchState` 或 `whenState` 消费：

```vue
<script setup lang="ts">
import type { SigmaStyles } from '@movk/sigma'

const customNodeState = { reach: 'out' }

const styles: SigmaStyles = {
  nodes: {
    matchState: 'reach',
    cases: {
      center: { color: '#f43f5e' },
      hit: { color: '#3b82f6' },
      out: { color: '#d1d5db', labelVisibility: 'hidden' }
    }
  }
}
</script>

<template>
  <SigmaGraph :data="data" :styles="styles" :custom-node-state="customNodeState" />
</template>
```

状态存在 sigma 内部，不污染 graphology 的属性，导出图数据时不会把 UI 状态一并带走。

### 自带 reducer

`nodeReducer` / `edgeReducer` 原样透传给 sigma 的构造函数，是 styles 表达不了时的逐帧逃生舱。签名与 sigma v4 一致：`(key, data, attributes, state, graphState, graph)`。常规视觉映射一律写 `styles`。

### 多实例

一页里可以放多张图。给每个实例一个 `id`，就能在组件树之外经 `useSigmaById(id)` 拿到它——用法与示例见 [`useSigmaById`](/docs/composables/use-sigma-by-id)。

::warning
每个 sigma 实例占 3 个 WebGL 上下文，浏览器上限多为 16 个。同屏超过五张图时最早的上下文会被强制丢弃、画布直接变空白，只在控制台留一行 `Too many active WebGL contexts`。列表页请做视口内懒挂载。
::

### 插槽内的定位

默认插槽排在占满高度的画布之后，走正常文档流。插槽内的任何面板都必须自行 `position: absolute`，否则会被挤到容器之外并被 `overflow` 裁掉。

```vue
<template>
  <SigmaGraph :data="data" style="height: 70vh">
    <div class="panel">…</div>
  </SigmaGraph>
</template>

<style scoped>
.panel {
  position: absolute;
  inset: 12px auto auto 12px;
}
</style>
```
