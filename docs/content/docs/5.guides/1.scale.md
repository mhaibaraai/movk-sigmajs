## 三档规模

先看基线。同一个确定性生成器分别产出 1k、5k、20k 节点，读数每次一致，便于横向比较：

:component-example{name="ScaleTiersExample" client-only="true" class="example-stage"}

::note
示例不自动加载——20k 节点、60k 边这一档建图要数百毫秒。按住画布拖动几秒，FPS 读数才有意义。
::

三档大致的体感分界：

::field-group
  :::field{name="1k 以内"}
  什么都不用调。默认配置下平移缩放都跟手。
  :::

  :::field{name="1k 到 10k"}
  开 `hideEdgesOnMove`，给 `labelRenderedSizeThreshold` 一个非零值。布局要么服务端算，要么走 worker。
  :::

  :::field{name="10k 以上"}
  一次性全量渲染开始吃力。改用「概览 + 按需展开」，首屏只上枢纽。
  :::
::

## 渲染侧开关的代价

同一份 5k 数据下逐项开关，看首帧与平移 FPS 的变化：

:component-example{name="ScaleSettingsExample" client-only="true" class="example-stage"}

三个开关的作用范围各不相同：

::field-group
  :::field{name="hideEdgesOnMove"}
  平移与缩放期间不画边。收益最大的一个——边通常比节点多几倍，而移动过程中本来也看不清。静止时边照常显示。
  :::

  :::field{name="labelRenderedSizeThreshold"}
  节点渲染尺寸小于该值时不画标签。`0` 表示全部渲染。大图上标签的排版与绘制开销可观，把它调到 8 以上通常立竿见影。
  :::

  :::field{name="labelDensity"}
  单位面积内允许的标签数量。降低它可以在放大后仍然保持标签稀疏，避免糊成一片。
  :::
::

这三项都是 sigma 自己的配置，经 `settings` 整体透传，本库不做任何包装——sigma 文档里的其他性能选项同样可用。

## 概览 + 按需展开

万级图不必一次性渲染完。[`sampleGraph()`](/docs/utils/sample-graph) 按度数抽出枢纽做首屏，点击节点时再用 [`useSigmaNeighborhood().expand()`](/docs/composables/use-sigma-neighborhood) 把邻域增量合入：

:component-example{name="ScaleOverviewExample" client-only="true" class="example-stage"}

```ts
// 首屏：只上枢纽
const overview = sampleGraph(full, 200)

// 展开：增量合入，已有节点不动
const { expand } = useSigmaNeighborhood()
await expand(key, id => $fetch(`/api/graph/nodes/${id}/neighbors`))
```

关键在于 `expand()` 内部走的是 `applyGraphDiff(..., { prune: false })`——只添不删，已有节点的坐标沿用。这条路径下 [`applyGraphDiff`](/docs/utils/apply-graph-diff) 的坐标保留才真正被用到：已经在屏上的节点不该因为一次展开而跳位。

真实项目里 `loadNeighbors` 就是一个服务端接口，前端始终只持有当前视野内的子图。

## 三条布局路径

坐标从哪来，决定了首屏要等多久：

:component-example{name="ScaleLayoutExample" client-only="true" class="example-stage"}

::field-group
  :::field{name="服务端预布局"}
  最稳。坐标随数据一起下发，前端一帧布局都不用算，首屏即最终形态。数据量大、拓扑变化不频繁时首选。
  :::

  :::field{name="主线程 ForceAtlas2"}
  `useSigmaLayout('forceatlas2', { worker: false }).assign()`。迭代期间页面完全无响应——2k 节点跑 30 轮就能明显感觉到。只适合小图或明确的加载态。
  :::

  :::field{name="worker ForceAtlas2"}
  `useSigmaLayout('forceatlas2').start()`。主线程全程不阻塞，用户可以边看边拖，代价是收敛过程可见。中等规模的默认选择。
  :::
::

worker 路径记得在合适的时机 `stop()`——布局收敛后继续迭代只是白烧 CPU，而且会让 [`useSigmaDrag()`](/docs/composables/use-sigma-drag) 的拖拽结果被持续覆盖。

## WebGL 上下文的硬上限

::warning
每个 sigma 实例占 **3 个 WebGL 上下文**（`sigma-edges` / `sigma-nodes` / `sigma-hoverNodes` 三张画布走 WebGL，另外四张是 2D），浏览器上限多为 16 个。

超出后最早的上下文被强制丢弃、画布直接变空白，**只在控制台留一行** `Too many active WebGL contexts`，不抛错也不降级。同屏实例请控制在四五个以内，列表页一律做视口内懒挂载。
::

[`SigmaMiniMap`](/docs/components/mini-map) 不受这条限制——它自己画 2D canvas，不创建 sigma 实例。
