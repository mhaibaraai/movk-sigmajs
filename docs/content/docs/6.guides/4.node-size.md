## size 不是像素

sigma v4 把 `itemSizesReference` 的默认值定为 `'positions'`，节点的 `size` 因此是**图坐标单位**，不是屏幕像素。渲染半径按下式换算：

`半径 ≈ size × 每图坐标单位对应的像素数`{lang="ts-type"}

而「每单位多少像素」由 `autoRescale` 把整张图铺进画布时算出，等于 `画布可用尺寸 / 坐标跨度`。两式合并即得到唯一重要的那条结论：

**决定节点视觉大小的是 `size` 与坐标跨度的比值，不是 `size` 的绝对数值。**

同样是 `size: 14`，坐标跨度 360 单位时渲染成半径 14px，跨度缩到 18 单位就变成 280px——比整块画布还大。切到 `screen` 语义则完全不受坐标影响：

## 本站示例的坐标约定

文档站所有示例把坐标跨度统一取在 **360 个单位**左右，正好对应示例容器的像素高度。于是每单位约等于 1px，示例里的 `size` 数值读起来就是像素半径，`size: 14` 画出来就是 14px。

这只是一个方便阅读的约定，不是 sigma 的规则。照抄示例时要留意：换成自己的数据后，坐标跨度多半不是 360，`size` 就得按新的比值重算。

布局算法的输出量级差别很大，几个常见的落点：

::field-group
  :::field{name="graphology-layout 的 circular / random"}
  默认 `scale` 为 1，坐标跨度只有 1~2 个单位。直接配 `size: 10` 会让每个节点铺满画布，要么把 `scale` 调到几百，要么把 `size` 压到 0.05 量级。
  :::

  :::field{name="circlepack"}
  默认 `scale` 同样是 1，但它按节点的 `size` 来排布，跨度会跟着 `size` 走，通常落在几十到一两百之间。
  :::

  :::field{name="forceatlas2"}
  跨度由参数与迭代过程决定，与输入量级基本无关。`inferSettings()` 给出的默认参数会把图收敛到几十个单位，360 单位的输入进去、几十个单位的结果出来，节点看上去就涨了近十倍。
  :::

  :::field{name="noverlap"}
  在现有坐标上做微调，是唯一保持原跨度的内置布局。
  :::

  :::field{name="服务端预计算的坐标"}
  量级由生产方决定。接入前先量一次 `x` / `y` 的极差，再据此定 `size`。
  :::
::

### 跑布局的场景直接切 screen

调 `scale` 只对 `circular` / `random` / `circlepack` 有效，ForceAtlas2 与 Noverlap 根本没有这个参数；而 worker 版的迭代型布局**每一帧都在回写坐标**，跨度一直在变，事后归一化也按不住。

所以只要图上会跑布局，最省事也最稳的做法就是让 `size` 不再依赖坐标：

```vue
<SigmaGraph :data="data" :settings="{ itemSizesReference: 'screen' }" />
```

本站 [useSigmaLayout](/docs/composables/use-sigma-layout) 与 [useSigmaDrag](/docs/composables/use-sigma-drag) 的示例都是这么处理的。

## 要 v3 的像素语义

v3 的默认值是 `'screen'`，`size` 直接就是屏幕像素、只随相机缩放走 `zoomToSizeRatioFunction`。从 v3 迁移过来又不想动数据的，把它传回去即可：

```vue
<SigmaGraph :data="data" :settings="{ itemSizesReference: 'screen' }" />
```

`settings` 整体透传，本库不做任何包装，sigma 的默认值也原样保留——这条不设为库的默认值，是为了不让本库与 sigma 官方文档给出不同的行为。

## 让初始视野把节点算进去

`autoRescale` 默认只按节点**坐标**取包围盒（`autoRescaleContent: 'positions'`），边缘节点的半径会被画布裁掉一部分。想让初始 framing 把半径也框进去：

```vue
<SigmaGraph :data="data" :settings="{ autoRescaleContent: 'nodes' }" />
```

`'labels'` 更进一步，连标签的排版框一起算。两者都需要在像素与坐标单位之间迭代求解，节点很多时有额外开销，大图上按需开启。
