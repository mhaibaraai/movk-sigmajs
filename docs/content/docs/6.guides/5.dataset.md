## 用法

本站示例的数据全部取自 sigma 官方 v4 网站的 `wikipedia.json`：维基百科上数据可视化相关词条构成的引用网络，2085 个节点、5409 条边、24 个社区，坐标由上游预先跑好。

完整数据集放在 `docs/public/data/wikipedia.json`，点击加载即可看到它原样渲染出来的样子：

:component-example{name="WikipediaDatasetExample" client-only="true" class="example-stage"}

## 原始数据不是 SerializedGraph

拿到的文件几乎不会正好是 graphology 的序列化格式，这份也一样：

```ts
interface WikipediaDataset {
  nodes: { key: string, label: string, tag: string, URL: string, cluster: string, x: number, y: number, score: number }[]
  edges: [source: string, target: string][]
  clusters: { key: string, color: string, clusterLabel: string }[]
  tags: { key: string, image: string }[]
}
```

三处需要换算：

::field-group
  :::field{name="color"}
  节点自身不带颜色，得按 `cluster` 去 `clusters` 里查。查不到时给一个兜底色，不要让 `undefined` 流进图数据。
  :::

  :::field{name="size"}
  节点自身不带尺寸。官方示例按 `10 + score * 1000` 换算，`score` 的上限是 0.042，于是 size 落在 10~52。
  :::

  :::field{name="分类字段"}
  看起来该用 `tag`，实际上 2085 个节点里有 1194 个是 `"unknown"`，做不了分类。分类一律用 `cluster`。
  :::
::

::note
这类「字段名对得上、语义对不上」的坑只能靠先量一遍数据发现。接一份新数据集之前，先把每个字段的取值分布打出来看看。
::

## 坐标与 size 必须一起缩放

原始坐标的跨度是 2860 个单位，而本站示例统一按 360 个单位的跨度组织。只把坐标缩到 360、`size` 原样留在 10~52，节点就会胀成原来的八倍——sigma v4 的 `size` 是图坐标单位，视觉半径看的是 `size` 与坐标跨度的比值，详见[节点尺寸与坐标量级](/docs/guides/node-size)。

所以归一化要同时作用在两者上，用的是同一个比例：

```ts
const extent = Math.max(maxX - minX, maxY - minY)
const ratio = 360 / extent

// 坐标平移到以原点为中心，再按 ratio 缩放
const x = (node.x - (minX + maxX) / 2) * ratio
const y = (node.y - (minY + maxY) / 2) * ratio

// size 按同一个 ratio 缩放，视觉比例才和原数据一致
const size = (10 + node.score * 1000) * ratio
```

完整实现见 `docs/app/utils/corpus.ts` 的 `loadWikipediaGraph()`。

## 大文件不要在挂载时加载

886 KB 的数据集加上 2085 个节点的建图，放进 `onMounted` 会让整页卡住，而且用户未必会看这个示例。示例里用一个按钮把加载推迟到真正需要的时候：

```vue
<script setup lang="ts">
const data = shallowRef<SerializedGraph | null>(null)

async function load() {
  data.value = await loadWikipediaGraph()
}
</script>

<template>
  <SigmaGraph v-if="data" :data="data" :settings="{ hideEdgesOnMove: true }" />
  <button v-else type="button" @click="load">加载</button>
</template>
```

万级节点的完整策略在[大规模图](/docs/guides/scale)里。

## 小示例用的是它的子集

本站其余示例调的 `demoGraph()` 不去 fetch 这个文件——它是同步函数，示例里 `const data = demoGraph()` 一行就要拿到数据。它读的是一份 160 节点的子集，随包打进 bundle，从 `docs/app/data/wikipedia-subset.json` 同步 `import`。

子集由脚本从完整数据集派生，从度数最高的节点做 BFS 展开，重新生成：

```bash
node docs/scripts/build-wikipedia-subset.mjs
```

`demoGraph({ nodes })` 再从子集里取一块连通子图，节点 key 重编为 `n0..nN`，`n0` 恒为整张图的枢纽。示例与文档正文都按这套稳定 id 引用节点，换数据源不会失效。

::note
规模示例用的 `createScaleGraph()` 仍然是合成数据。那些示例要 2k / 5k / 20k 个节点，官方公开数据目录里最大的图也只有 2085 个——上游那批万级数据集是构建时从 SNAP 下载、不入库的。规模示例讲的是体量不是语义，合成数据反而能精确控制节点数。
::
