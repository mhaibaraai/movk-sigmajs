## 用法

封装是加法，不是围墙。库没覆盖的原生能力，用户必须仍然能用——这一页的说服力全在「不用库的任何东西也能跑」：

:component-example{name="EscapeHatchExample" client-only="true" class="example-stage"}

示例里除了 `<SigmaGraph :graph>` 这一个组件，没有用到本库的任何 composable、控件或工具函数。事件订阅、settings 读写、图数据修改、相机控制，全部是原生 API。

`SigmaGraph` 在这条路径下只做两件事：在客户端创建实例、在卸载时销毁。剩下的都是你的。

## 五条保证

::field-group
  :::field{name="不代理实例"}
  [`useSigma()`](/docs/composables/use-sigma) 返回的是原生 `Sigma` 与 `Graph`，不包 Proxy、不做包装。`@ready` 事件给出的也是实例本身。
  :::

  :::field{name="不做 settings 白名单"}
  `settings` 整体透传，不逐字段枚举也不过滤未知键。传进去的任何键都能从 `sigma.getSettings()` 原样读回，sigma 新增的配置项无需本库升级即可使用。
  :::

  :::field{name="双数据通道"}
  传 `data` 由库做增量 diff；传 `graph` 则库**完全不碰数据**，只负责渲染与生命周期。上面的示例走的就是第二条。
  :::

  :::field{name="不 re-export 上游"}
  `sigma` 与 `graphology` 保持 peer 依赖，本库不转发它们的任何值或类型——整个应用里只有一份实例，也不会因为本库的版本区间限制你升级上游。
  :::

  :::field{name="用户的 reducer 在链首"}
  `nodeReducer` / `edgeReducer`（`SigmaGraph` 的独立 props）原样透传给构造函数，是需要逐帧计算显示数据时的逃生舱。常规视觉映射一律写 `styles`。
  :::
::

## 逐步回到库里

逃生舱不是非此即彼。上面每一条都可以单独用，组合出你要的粒度：

```vue
<script setup lang="ts">
import Graph from 'graphology'

// 数据自己管
const graph = new Graph()

// 但选中高亮用库的
const { selected } = useSigmaSelection()
</script>

<template>
  <SigmaGraph :graph="graph">
    <!-- 控件也用库的 -->
    <SigmaControls position="top-right">
      <SigmaZoomControl />
    </SigmaControls>
  </SigmaGraph>
</template>
```

反过来，用了 `data` 通道也随时可以拿原生实例做库没提供的事：

```ts
const { sigma, whenReady } = useSigma()

const instance = await whenReady()
instance.on('doubleClickEdge', handler) // 原生订阅，与 useSigmaEvents 并存
instance.setSetting('zoomToSizeRatioFunction', fn) // 库没包装的设置
```

::warning
唯一要留意的是 reducer。`nodeReducer` 在 v4 已不是 `Settings` 的键，直接调 `sigma.setSetting('nodeReducer', fn)` 既不生效也过不了类型检查——它只能走 `SigmaGraph` 的 `nodeReducer` prop。
::

## 类型从原包取

本库不转发上游类型，需要时从原包直接 import：

```ts
import type Graph from 'graphology'
import type { SerializedGraph } from 'graphology-types'
import type Sigma from 'sigma'
import type { NodeDisplayData } from 'sigma/types'
```

本库自己的类型才从根出口取：

```ts
import type { SigmaContext, SigmaPrograms } from '@movk/sigma'
```

::warning
`sigma` 的每个子路径在模块顶层就读 `WebGL2RenderingContext`，静态 `import 'sigma'` 会让 SSR 直接 ReferenceError。上面这些都是 `import type`，编译期擦除，不受影响。需要运行期的值一律走动态 `import()`，渲染原语用 [`defineSigmaPrimitives()`](/docs/utils/define-sigma-primitives)。`graphology` 没有这个问题，可以正常静态 import。
::
